Git Workflow & Repository Organization

This project is now under active development and will be worked on by multiple AI coding assistants (Replit, Codex, ChatGPT, etc.).

I want GitHub to become the single source of truth.

Objectives

Reorganize the Git workflow to follow professional software development practices.

Branch Strategy

Keep main as the stable production branch.

Create the following feature branches:

feature/homepage-polish
feature/about-page
feature/contact-form
feature/footer-redesign
feature/seo
feature/performance
feature/mobile-optimization

Do not merge them yet.

Explain which branch should be used for each future task.

Development Rules

From now on:

Never work directly on main.
Every new feature must start from its own feature branch.
Commit changes in small logical commits.
Push feature branches to GitHub after each completed milestone.
Merge into main only after the feature has been tested.
Repository Cleanup

Assets are organized.

Branding assets remain untouched.

One adjustment I'd make

Rather than creating all of the feature branches immediately, I'd only create them when work actually starts. For example:

Start feature/about-page when you're ready to build the About page.
Merge it into main after testing.
Then create feature/footer-redesign for the footer work.

That keeps your repository cleaner and makes it easier to see what work is active versus planned. The naming convention can still be documented now, but the branches themselves can be created as neede
